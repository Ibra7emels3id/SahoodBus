# ربط Wasender API مع حافلة سهود

تمت مراجعة وثائق Wasender API في 25 أغسطس 2026 قبل بدء أي ربط فعلي. يوفر المزود إدارة جلسات واتساب، وإنشاء جلسة وربطها عبر رمز QR، وإرسال رسائل نصية، والاستعلام عن سجل الرسائل. كما توثق الخدمة webhooks مستقلة لتغير حالة الجلسة وتحديث QR وحالة الرسالة وإيصال الرسالة، وهي الأحداث اللازمة لبناء شاشة مراقبة داخل لوحة المدير.[1][2]

سيقتصر النظام على حفظ بيانات التشغيل الآتية في MongoDB: معرّف جلسة Wasender غير السري، حالة الاتصال، المعرّف الخارجي للرسالة، حالة الرسالة وتوقيت تغيرها، والبيانات المعروضة في سجل التدقيق. لن تُحفظ مفاتيح API أو رموز الوصول في MongoDB أو ملفات التصدير؛ ستدار كإعدادات بيئية آمنة فقط.

| القدرة المطلوبة | مسار النظام المخطط | مصدر الحالة |
|---|---|---|
| ربط رقم واتساب | شاشة مدير تنشئ/تتابع جلسة وتعرض رمز QR من المزود | حالة الجلسة وتحديث QR |
| إرسال تلقائي | رسالة نصية بعد حفظ الحجز عند اتصال الجلسة | استجابة الإرسال ثم webhook الحالة |
| إرسال يدوي | زر في سجل الحجز يعيد إرسال نفس التفاصيل بإقرار الموظف | سجل الإرسال في النظام |
| المتابعة | بطاقة اتصال وسجل رسائل قابل للفلترة حسب الحالة | webhooks حالة الرسالة والإيصال |

> لا يمكن ضمان وصول الرسالة إلى جهاز الراكب؛ سيفرق النظام بوضوح بين **قبول الطلب من المزود** و**الإرسال** و**التسليم** و**القراءة** و**الفشل** متى أتاحها المزود، مع تسجيل السبب عند الفشل.
