# عقود واجهة برمجة التطبيق

يفصل هذا المشروع واجهة React داخل `client/` عن منطق الأعمال داخل `server/`. لا تستدعي الواجهة قاعدة البيانات مباشرة؛ بل تتعامل مع إجراءات tRPC المعتمدة على العقود المعرّفة في `shared/contracts.ts`. يضمن ذلك بقاء التحقق من المدخلات وقواعد الصلاحيات في طبقة الخادم.

| المجال | الإجراء | المدخلات | قاعدة الصلاحيات |
|---|---|---|---|
| النطاق التشغيلي | `operations.dashboard` | لا شيء | المدير يرى الكل، ومستخدم الفرع يرى فرعه فقط. |
| الرحلات | `booking.trips.create` | `TripInput` | يحفظ المسار، الحافلة، السائق الأول والثاني، الموعد، وعدد المقاعد. |
| الحجوزات | `booking.reservations.create` | `ReservationInput` | يُسجّل الحجز على فرع مستخدم الفرع تلقائياً. |
| التقارير | `booking.reports.summary` | `ReportFilters` | يطبّق الفترة والفرع والرحلة، ويتجاهل الخادم اختيار فرع مختلف لمستخدم الفرع. |
| الخزنة | `booking.cashbox.list/create` | `ReportFilters` أو `CashboxTransactionInput` | يربط الحركة بالفرع، ويمكن ربطها برقم الحجز عند توفره. |
| المصروفات | `booking.expenses.create` | `ExpenseInput` | المدير فقط أو مستخدم الفرع ضمن فرعه. |

تضم الخلفية أيضاً إجراءات القراءة `booking.trips.list` و`booking.reservations.list` و`booking.expenses.list`، إلى جانب `booking.reports.summary`. تعمل هذه الإجراءات من `server/routers/booking.ts` وتفرض نطاق الفرع **على الخادم** قبل إرجاع أي صفوف أو إنشاء أي عملية جديدة.

> **قاعدة عزل الفروع:** يجب أن يكون `branchId` القادم من الجلسة هو المصدر الحاكم لمستخدم الفرع، لا القيمة التي يرسلها المتصفح. تستخدم جميع إجراءات البيانات هذه القاعدة قبل القراءة أو الكتابة.

تبدأ النسخة الأولى ببيانات عرض مرئية في الواجهة لتسهيل مراجعة تجربة الاستخدام، ثم تستبدل هذه البيانات باستعلامات الإجراءات أعلاه عند إدخال بيانات التشغيل الحقيقية.
